# NAS Comic Compressor 1.1

NAS의 만화책 이미지 폴더 중 **아직 압축되지 않은 폴더만** 찾아 반디집(bz.exe)으로 CBZ(또는 ZIP)를 만드는 Windows GUI 프로그램입니다.

## 빠른 사용법

1. `NAS_Comic_Compressor.exe`를 만화책 최상위 폴더(예: `Y:\만화책`)에 넣고 실행합니다.
   EXE가 있는 폴더가 작업 폴더로 자동 지정됩니다. `[폴더 선택…]`으로 다른 폴더(UNC `\\NAS\Comics` 포함)도 고를 수 있습니다.
2. 반디집 경로는 자동으로 찾습니다. 못 찾으면 `[경로 변경…]`에서 `C:\Program Files\Bandizip\bz.exe`를 선택하세요.
3. `[압축 대상 검색]`을 누르면 대상 목록이 표시됩니다. 체크를 해제해 일부만 제외할 수 있고, 행을 더블클릭하면 해당 폴더가 열립니다.
4. `[압축 시작]`을 누릅니다. `[일시정지]`는 현재 항목을 마친 뒤 멈추고, `[중단]`은 진행 중 항목을 취소하고 임시파일을 지웁니다(원본은 보존).
5. 작업이 끝나면 요약이 표시되고, CSV/로그는 `%LOCALAPPDATA%\NASComicCompressor\logs`에 저장됩니다(`[로그 폴더]` 버튼).

## 판별 규칙

| 구조 | 처리 |
|---|---|
| A. `작품/01권/*.jpg` | `작품/01권.cbz`처럼 권별로 압축 |
| B. `웹툰A/*.jpg` | `웹툰A.cbz` |
| C. `원피스/01권.zip …` | 그대로 둠 |
| D. `01권.zip` + `02권/` | `02권`만 압축. `01권/` 폴더가 있어도 `01권.zip`이 있으면 제외 |
| E. 여러 단계 하위 폴더 | 재귀 탐색해 이미지가 직접 든 **말단 폴더**만 압축. 상위 폴더는 통째로 압축하지 않음 |
| F. `cover.jpg` + `01권/` | `01권`만 압축하고 `cover.jpg`는 건드리지 않음 |

추가 규칙은 다음과 같습니다.

- 같은 위치에 `<폴더명>.zip/.cbz/.rar/.cbr/.7z/.tar` 중 하나라도 있으면 제외합니다. 기존 파일은 절대 덮어쓰지 않습니다.
- 압축파일에는 그 폴더에 직접 들어 있는 **이미지 파일만** 넣습니다. 상위 경로 없이 `001.jpg`처럼 들어가고, txt나 내부 zip 같은 다른 파일은 넣지 않고 보존합니다.
- 하위 폴더를 읽지 못하면(권한·네트워크 오류) 그 상위 폴더도 압축하지 않습니다.
- 작업 루트 폴더 자체는 압축하지 않습니다.
- **표지 낱장 보호(기본 켜짐)**
  - 작품 폴더에 `1권.zip …`과 함께 있는 낱장 이미지 5장 이하(`0000.jpg`, `cover.jpg` 등)는 압축하지 않고 그대로 둡니다.
  - `cover`, `0000`, `folder`, `표지` 같은 표지 이름의 이미지만 있는 폴더도 제외합니다.
- **최소 이미지 수(기본 2장)**: 이보다 적은 폴더는 한 장짜리 압축파일이 되지 않도록 제외합니다.
- `.`으로 시작하는 폴더(`.sync` 등)와 NAS 시스템 폴더(`@eaDir`, `#recycle`, `#snapshot` 등)는 탐색하지 않습니다.
- 심볼릭 링크와 정션은 따라가지 않습니다.
- 파일 메타데이터만으로 판별하고 이미지를 디코딩하지 않습니다. 압축할 때 앞 16바이트를 보고 확장자와 맞지 않는 이미지는 경고로 기록합니다.

## 압축 처리 순서 (항목마다)

1. 검색 이후 폴더 내용이 바뀌지 않았는지, 출력 파일이 생기지 않았는지 다시 확인합니다.
2. `bz.exe c -fmt:zip -l:0 -y -r- -consolemode:utf8 <임시파일> .\001.jpg …`를 `shell=False`로 실행하고 인수는 리스트로 넘깁니다.
   - 파일이 많아 명령줄 한도를 넘으면 `bz.exe a`로 나눠 추가합니다.
   - 임시파일 이름은 같은 폴더의 `.ncc-<랜덤>.tmp.zip`입니다. 중단되거나 강제 종료되어도 불완전한 `.cbz`는 남지 않습니다.
3. `bz.exe t`로 무결성을 검사합니다.
4. 압축파일 내부 목록과 각 파일 크기가 원본과 정확히 같은지 Python으로 다시 검사합니다. 파일명 인코딩이 깨졌는지도 여기서 확인합니다.
5. 검사를 모두 통과해야 최종 `.cbz`로 이름을 바꿉니다. 같은 이름이 있으면 실패 처리하고 덮어쓰지 않습니다.

압축 방식의 기본값은 **저장(-l:0)**입니다. JPG/WEBP는 이미 압축된 형식이라 다시 압축해도 크기가 거의 줄지 않고 시간만 듭니다.

### 이전(GPT) 버전 오류에 대한 대응

이전 버전 로그에서 실패 대부분이 `[Errno 13] Permission denied: ...\.ncc-xxxx.tmp\result.zip`이었습니다.
압축과 반디집 검사(All OK)까지는 성공했지만, 만들어진 파일을 여는 단계에서 다른 프로그램이 파일을 잡고 있었습니다. NAS 동기화 클라이언트(`.sync` 폴더 존재)나 백신이 원인으로 추정됩니다.
새 버전은 다음과 같이 대응합니다.

- 파일 잠금(PermissionError)이 나면 최대 60초 동안 간격을 늘려 가며 재시도합니다.
- 실패가 연속으로 N회(기본 10회) 나면 자동으로 중단합니다. 수천 건이 계속 실패하는 상황을 막기 위해서입니다.
- 프로그램은 동시에 하나만 실행됩니다.
- 이전 버전이 남긴 `.ncc-*.tmp` 폴더는 검색할 때 찾아내고 `[임시파일 정리]`로 지울 수 있습니다.
  안에 `result.zip` 외 다른 파일이 있으면 지우지 않습니다.
- 이전 버전이 만든 `.zip`이 있는 폴더는 같은 이름 압축파일로 보고 자동으로 제외합니다.

## 원본 삭제 옵션 (기본 꺼짐)

`압축 성공한 원본 폴더 삭제`를 켜면 경고창이 뜹니다. 아래 조건을 **모두** 만족할 때만 삭제합니다.

- 반디집 무결성 검사를 통과했습니다.
- 압축파일 내부의 파일 목록과 크기가 원본과 일치합니다.
- 원본 파일과 압축파일 내부 파일의 **SHA-256 해시**가 모두 일치합니다.
- 폴더에 이미지 외 파일이나 하위 폴더가 없습니다.
- 검색 이후 원본의 크기와 수정 시간이 바뀌지 않았습니다.
- 사용자가 작업을 중단하지 않았습니다.

NAS에서 지운 파일은 휴지통으로 가지 않을 수 있으니, 처음에는 원본 보존으로 실행해 결과를 확인하는 것을 권장합니다.

## 실시간 작업 현황 / 목록 메뉴

- 가운데 패널에는 현재 압축 중인 작품과 권, 진행 수, 성공·실패·건너뜀 수, 처리 용량, 속도, 경과·남은 시간이 표시됩니다. `[원본 폴더 보기]`·`[결과 위치 보기]`로 바로 이동할 수 있습니다.
- `목록 보기`에서 전체, 진행·대기, 실패만, 완료, 건너뜀 중 하나를 골라 볼 수 있습니다. `진행 중 항목 따라가기`를 켜면 목록이 현재 항목으로 자동 스크롤됩니다.
- 목록을 우클릭하면 원본 폴더, 작품 폴더, 결과 파일 위치(탐색기에서 선택), 결과 파일 열기, 경로·메시지 복사, 선택 항목 체크/해제를 쓸 수 있습니다. 행을 더블클릭하면 원본 폴더가 열립니다.

## 로그/CSV

- CSV(UTF-8 BOM, 엑셀에서 바로 열림) 열: 시간, 구분(검색/압축), 원본 경로, 상태(성공/실패/건너뜀/취소/미실행), 설명, 이미지 수, 원본 바이트, 출력 경로, 출력 바이트, 원본 처리
- 검색할 때마다 `*_scan_*.csv`가, 압축할 때마다 `*_run_*.csv`와 `*.log`(반디집 출력 포함)가 생깁니다.

## GitHub Actions 빌드

main에 푸시하면 Windows 환경에서 테스트를 실행하고 EXE를 빌드합니다. 결과는 Actions 실행 화면의 Artifacts에 올라갑니다.
`v1.1.0`처럼 `v`로 시작하는 태그를 푸시하면 Releases에 EXE와 SHA-256 파일이 첨부됩니다.

## 직접 빌드

Python 3.12 이상을 설치하고 `build.bat`을 실행하면 `dist\NAS_Comic_Compressor.exe`가 생성됩니다.
실제 반디집으로 테스트하려면 `set NCC_REAL_BZ=C:\Program Files\Bandizip\bz.exe` 후 `python -m pytest -q tests`를 실행하세요.

## 제한사항

- 일시정지는 현재 항목이 끝난 뒤에 적용됩니다. 압축 중인 반디집 프로세스는 중간에 멈추지 않습니다.
- 경로가 260자를 넘으면 Windows의 긴 경로 설정(LongPathsEnabled)이 없을 때 실패할 수 있습니다. 실패는 항목 단위로 기록되고 원본은 보존됩니다.
- 압축파일 내부 파일명은 UTF-8이어야 검증을 통과합니다. 일본어 파일명 등이 깨졌다는 실패가 나오면 반디집 설정에서 압축 시 UTF-8 파일명 사용 여부를 확인하세요.
